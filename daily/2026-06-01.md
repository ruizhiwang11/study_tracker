## C++ — Overload Resolution + Name Lookup

### What was studied
- Overload resolution: 3-phase process (name lookup → viable filter → best viable)
- ICS ranking: exact match > qualification > promotion > conversion > user-defined > ellipsis
- Lvalue/rvalue reference overloading + reference collapsing
- Concepts partial ordering and subsumption — most constrained wins
- Name lookup: one core subroutine (single scope search), three modes:
  - Unqualified: subroutine applied scope by scope outward, stops at first match
  - ADL: subroutine repeated over namespaces of argument types (second pass, not parallel)
  - Qualified (`X::name`): subroutine applied to X only
- Dependent base class rule: base class depending on template param is NOT searched by unqualified lookup — must use `this->` or `Base<T>::`
- Hidden friend functions: defined inside class body, lives in enclosing namespace, only reachable via ADL
- `operator<<` inside vs outside: both found via ADL, outside is convention for ostream ops

### Key insights
- Name lookup is ONE subroutine applied differently — not three separate mechanisms
- ADL is a second pass of the same subroutine over argument namespaces, not parallel search
- Qualified lookup left side (`N::`) ignores ordinary variables — only sees namespaces/classes
- Hidden friends prevent namespace pollution and guarantee ADL always finds the function
- CRTP must use `this->` or qualified call because dependent base is skipped by unqualified lookup
- Past `ostream` compile errors: print function was in wrong namespace — ADL on msg type searched msg's namespace and found nothing
